# 提案：「我家桃园年历」——个性化全年农事挂图生成器（v5.0 头号功能）

> 给开发者的完整构想书。读完即可开工：目标、功能定义、技术方案、里程碑、验收标准都在这里。
> 项目底线（务必遵守）：**全免费、零依赖、不收集信息、文案口语化、农学参数有出处**（见 AGENTS.md）。

---

## 一、为什么做它（背景与价值）

现在的小助手有个隐含局限：**所有答案都在手机屏幕里**。而咱们的主力用户是四五十岁往上的桃农——他们真正的习惯是把一张农事挂图**贴在屋里墙上**，干活前瞟一眼。每年各县农技站印的挂图之所以年年有人要，就是这个原因。

但市面挂图是"一刀切"的：日期笼统（"4 月上旬疏果"）、不分品种、不看今年天气。而我们的网站恰恰**已经算出了所有个性化日期**——你家在哪个村、你家种的是晚蜜还是大久保、你上报的真实花期、今年虫害窗口在哪几天。

**把散落在六个模块里的个性化日期，汇成一张能打印、能发微信群的年历挂图**——这是把整个项目的价值"压"成一张纸。也是把用户从"偶尔打开网页"变成"全年留在墙上"。

## 二、用户故事

| 谁 | 故事 |
|---|---|
| 桃农老李 | 选好村子、勾上自家 3 个品种、点「生成年历」，打印一张 A4 贴墙上，全年干活前瞟一眼 |
| 群里的王姐 | 长按生成长图发到村微信群，全村人存图 |
| 科技小院小王 | 打印 50 份带二维码的挂图，走访时发给农户（二维码扫开就是这个网站，自然引流） |

## 三、功能定义

### 输入（都是现成的，零新增概念）
- 产区（已选中的）
- 品种勾选（从当前国家的品种表多选；默认全选）
- 两个开关：是否套袋（决定套袋节点是否上历）、有无灌溉条件（决定浇水节奏列）

### 计算（全部复用现有函数，不新造农学逻辑）
`loadRegion()` + 有效花期（**自动跟随物候上报**）+ `pestWindows()` + 品种采收窗口 + 疏果/套袋节点 + 封冻水/需冷量结论，汇总成一张「月份 × 事项」数据表：
- 每月列出：该月的关键日期（几号、什么事、涉及品种、颜色）
- 无花期时（比如冬季生成）用"待估"占位并提示"开春生成年历会更准，或先上报花期"

### 输出（两种，全客户端生成）
1. **A4 打印版**：`@media print` 专用排版 + `window.print()`，浏览器自带"另存为 PDF"。顶部大标题（我家桃园 · 2027 年历 · 大华山镇），12 个月分栏，底部图例 + 网站二维码
2. **微信长图**：`<canvas>` 自绘 9:16 长图 → 一键保存/分享（老手机不支持 canvas 下载时降级为"截图提示"）

### 二维码（引流闭环）
用纯 JS 二维码生成（约 100 行的公开算法实现，可直接内联，不算外部依赖）指向 `https://taoyuan-weather.pages.dev/`，印在挂图角落。

## 四、技术方案要点

- **零依赖**：打印走打印样式；长图走原生 canvas（注意 devicePixelRatio 保证清晰度）；二维码算法内联——不引任何 CDN/库
- **计算层复用**：`loadRegion` / `buildPlan` / `pestWindows` / 品种表已参数化（任务三成果），直接调用，不要复制粘贴逻辑
- **中英双语**：挂图标题/图例/月份名走 `T()`；EN 版月份用 Jan–Dec
- **断网可用**：年历生成只用已缓存数据（localStorage 有 1 小时缓存），断网时"生成年历"按钮禁用并提示
- **文件位置**：年历生成逻辑建议独立成页面内一个新 section `#wallcal`（或查询参数 `?view=cal` 的简化全屏视图，利于打印）

## 五、里程碑（建议 2–3 周）

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| M1（~1 周） | 数据汇总层：把六模块日期聚合成"月份×事项"表（纯函数 + 冒烟测试） | 用平谷/蒙阴/佐治亚三地数据各生成一次数据表，人工核对与页面各模块一致 |
| M2（~1 周） | A4 打印版：打印样式 + 分页控制 + 二维码 | 打印预览 1–2 页排布美观；真实打印一次贴墙测试 |
| M3（3–4 天） | 微信长图 canvas + 保存/分享 + EN 版 | 手机上长图清晰可读、能保存相册 |

## 六、验收标准（逐条可测）

- [ ] 平谷城区 + 晚蜜/大久保 + 已上报花期：年历上的疏果/套袋/各品种采收/虫害窗口日期与页面对应模块**逐日一致**
- [ ] 换 5 个品种勾选组合，年历只显示勾选品种的条目
- [ ] 冬季（12–2 月）生成：盛花等日期显示"待估"占位而非空白或报错
- [ ] A4 打印预览无截断、无跨页断行；黑白打印机下图例仍可区分（形状/文字冗余，不只靠颜色）
- [ ] 长图在 3 年内的安卓机上生成 <3 秒、文字清晰不模糊
- [ ] 中→英→中往返，年历文案正确切换
- [ ] 断网打开页面（已缓存数据）：年历仍可生成
- [ ] `node --check` 通过；375px 宽度入口按钮不破版

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| canvas 中文换行/字体差异 | 按字宽逐行排版（不依赖 measureText 以外的 API）；主流机型过一遍 |
| 打印分页把一个月切成两半 | 每月一个打印块，`break-inside: avoid` |
| 花期未估/未上报 | 占位符 + 顶部提示"上报花期后重新生成会更准"（引流到物候上报） |
| 挂图与页面更新不同步 | 挂图角落印"生成于 xx 日期"，建议每月重新生成 |

## 八、备选方向（如果这个不合口味，一句话版）

1. **预警到手机**：企业微信群机器人 + ntfy 主动推送（构想书在 git 历史 `66dbf49`，`git show 66dbf49:docs/PROPOSAL-alert-push.md` 可找回）——需要 Cloudflare D1/Workers，偏后端
2. **适老化语音模式**：「念给我听」按钮把当天安排读出来 + 语音上报花期（Web Speech API，零成本）——交互改造为主
3. **拍照问诊**：AI 识别病虫害——最吸睛但需要训练数据/付费模型，误判风险高（农户可能照着乱打药），不建议现阶段做

## 九、你需要提前准备的

一台打印机（测试打印效果）+ 三部不同年代的安卓手机（canvas 兼容测试）。其余全部现成。
